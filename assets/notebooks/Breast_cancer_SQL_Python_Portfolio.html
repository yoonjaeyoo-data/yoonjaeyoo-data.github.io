1. Project Overview¶

This project analyzes the Wisconsin Diagnostic Breast Cancer (WDBC) dataset to classify breast tumors as malignant (M) or benign (B).

Project Goal¶

The goal of this project is to build an end-to-end data analysis workflow using Neon PostgreSQL, SQL, and Python, compare several machine learning classification models, and identify a model that performs well at detecting malignant tumors.

Because this is a diagnostic classification problem, malignant-class recall is treated as a primary model-selection metric rather than relying on accuracy alone. A false negative occurs when an actual malignant tumor is incorrectly classified as benign, so reducing missed malignant cases is an important consideration in this analysis.

To reflect a realistic data workflow, I first stored the dataset in Neon PostgreSQL and used SQL to query and summarize the data. I then brought the queried data into Python for exploratory data analysis and feature analysis before building and comparing Logistic Regression, Random Forest, and Support Vector Machine (SVM) models. Model performance was evaluated using accuracy, precision, recall, F1-score, ROC-AUC, and false-negative counts.

2. Dataset & PostgreSQL Setup¶

I used the WDBC dataset, which contains 569 tumor samples and 30 numerical diagnostic features derived from digitized images of breast mass cell nuclei.

The target variable I used is:

M = Malignant

B = Benign

In addition to the target variable, I identified an 'id' field in the dataset that is used only as a record identifier, so I excluded it from model training.

Feature Description¶

I worked with 30 numerical diagnostic features. These features are derived from 10 cell-nucleus characteristics, with three measurements calculated for each characteristic: the mean, standard error (_se), and worst value (_worst), where the worst value represents the mean of the three largest measurements.

3. SQL Data Exploration¶

Before moving into Python modeling, I used SQL to validate the dataset and summarize differences between malignant and benign cases.

I found that the dataset contained:

  • 357 benign cases

  • 212 malignant cases

I also used SQL aggregation to compare several tumor characteristics:

  • Mean Radius: Benign = 12.15, Malignant = 17.46

  • Mean Area: Benign = 462.79, Malignant = 978.38

  • Mean Texture: Benign = 17.91, Malignant = 21.60

From these SQL results, I found that malignant tumors had higher average radius, area, and texture values than benign tumors.

To explore the radius pattern further, I used CASE WHEN to divide tumors into Small, Medium, and Large radius groups. Rather than choosing arbitrary cutoff values, I defined the groups using the 33rd and 67th percentiles of radius_mean. I then calculated the number of observations and the proportion of malignant cases within each radius group.

This additional SQL analysis allowed me to examine whether the proportion of malignant cases changed across different tumor-size groups before moving on to feature distributions and relationships in Python.

query = """
WITH radius_cutoffs AS (
    SELECT
        PERCENTILE_CONT(0.33) WITHIN GROUP (ORDER BY radius_mean) AS low_cutoff,
        PERCENTILE_CONT(0.67) WITHIN GROUP (ORDER BY radius_mean) AS high_cutoff
    FROM breast_cancer
),
radius_groups AS (
    SELECT
        diagnosis,
        radius_mean,
        CASE
            WHEN radius_mean <= low_cutoff THEN 'Small'
            WHEN radius_mean <= high_cutoff THEN 'Medium'
            ELSE 'Large'
        END AS radius_group
    FROM breast_cancer
    CROSS JOIN radius_cutoffs
)

SELECT
    radius_group,
    COUNT(*) AS sample_count,
    ROUND(
        AVG(CASE WHEN diagnosis = 'M' THEN 1.0 ELSE 0 END)::numeric,
        3
    ) AS malignant_rate
FROM radius_groups
GROUP BY radius_group
ORDER BY
    CASE radius_group
        WHEN 'Small' THEN 1
        WHEN 'Medium' THEN 2
        WHEN 'Large' THEN 3
    END;
"""

6. Machine Learning Model Development¶

The EDA showed that several individual features were strongly associated with diagnosis, but none of them could completely separate malignant and benign tumors on their own. Based on this, I used the full set of 30 diagnostic features to build and compare classification models.

The id column was excluded because it does not contain predictive information, while diagnosis was used as the target variable and encoded as:

  • 0 = Benign
  • 1 = Malignant

To evaluate model performance on unseen data, the dataset was split into training and test sets. I used stratified sampling to preserve the original malignant–benign class distribution in both sets, which is especially important because malignant cases make up the smaller class in the dataset.

The goal of this stage was not simply to maximize overall accuracy, but to compare models based on how reliably they identify malignant tumors, with particular attention to recall and false-negative predictions.

Modeling Strategy¶

I compared three classification models: Logistic Regression, Random Forest, and Support Vector Machine (SVM).

For Logistic Regression and SVM, I used StandardScaler because both models can be affected by differences in feature scale. I did not scale the inputs for Random Forest because tree-based models are not sensitive to feature magnitude in the same way.

To compare the models more reliably, I used stratified 5-fold cross-validation, which allowed each model to be evaluated across multiple train-validation splits while preserving the proportion of benign and malignant cases in each fold.

I compared the models using accuracy, precision, malignant-class recall, F1 score, and ROC-AUC. Because missing a malignant case was the error I wanted to pay particular attention to, I placed greater emphasis on malignant-class recall when selecting the final model.

Cross-Validation Results & Model Selection¶

Logistic Regression achieved the highest cross-validated malignant-class recall (0.953) and ROC-AUC (0.996), although its performance was very close to SVM (recall 0.947, ROC-AUC 0.995).

Because malignant-case detection was the primary concern in this project, I gave greater weight to recall when comparing the models. I selected Logistic Regression as the final model because it achieved slightly stronger recall and ROC-AUC while also allowing me to examine its feature coefficients and interpret how individual tumor characteristics contributed to the predictions.

Holdout Test Results¶

8. Model Interpretation¶

To better understand the final Logistic Regression model, I examined the standardized coefficients of all 30 diagnostic features.

I used the coefficient magnitudes to compare how strongly the features were associated with the model's predictions, while interpreting the ranking cautiously because several predictors are highly correlated with one another.

I also converted the coefficients into odds ratios (exp(coefficient)) to make their magnitude easier to interpret. Because the features were standardized before modeling, an odds ratio shows how the odds of a malignant prediction change with a one-standard-deviation increase in a feature, while the other predictors are held constant.

For example, the coefficient for Worst Texture was approximately 1.434, corresponding to an odds ratio of about 4.20. This means that a one-standard-deviation increase in Worst Texture was associated with approximately 4.2 times higher odds of a malignant prediction, holding the other predictors constant.

Note: In the WDBC dataset, “Worst” refers to the mean of the three largest measurements for a given feature.

Key Findings: Model Coefficients Show Different Predictive Patterns¶

I found the largest coefficient magnitudes for Worst Texture, Radius Standard Error, and Worst Symmetry.

These results were not identical to the earlier correlation ranking. The correlation analysis examined each feature's relationship with diagnosis individually, while the Logistic Regression coefficients reflected each feature's contribution after the other predictors were considered at the same time.

I interpreted the coefficient ranking cautiously because several tumor size-related variables, such as radius, perimeter, and area, are highly correlated with one another. This multicollinearity can redistribute coefficient magnitudes across related predictors, so I treated the coefficients as an interpretive reference rather than as a definitive ranking of feature importance.

Because malignant cases were encoded as 1 and benign cases as 0, a positive coefficient indicates that higher values of a feature are associated with a higher probability of a malignant prediction, while a negative coefficient indicates the opposite direction.

Rather than treating the coefficient ranking as a direct measure of feature importance, I used it to understand broader predictive patterns in the final model. The relatively large coefficient for Worst Texture, for example, suggests that texture-related information contributed meaningfully to the model alongside the strongly correlated size- and shape-related features.

9. Conclusion¶

This project combined SQL, PostgreSQL, Python, EDA, and machine learning to build an end-to-end breast cancer classification workflow.

The exploratory analysis showed clear differences between malignant and benign tumors across several tumor characteristics, particularly size- and shape-related features. I then compared Logistic Regression, Random Forest, and SVM using stratified cross-validation.

Among the three models, Logistic Regression achieved the highest cross-validated malignant-class recall (0.953) and ROC-AUC (0.996), so I selected it as the final model. On the separate test set, it achieved 0.965 accuracy, 0.929 recall, and 0.996 ROC-AUC, with 3 malignant cases incorrectly classified as benign.

One of the main takeaways from this project was that overall accuracy alone did not fully reflect the goal of the analysis. Because missing a malignant case was the error I wanted to pay particular attention to, malignant-class recall and false-negative predictions were more closely aligned with the model-selection objective.

The feature analyses also provided two complementary views of the data. Correlation analysis highlighted concave-point and perimeter-related measurements as strongly associated with diagnosis, while the final Logistic Regression model placed larger standardized weights on features such as Worst Texture, Radius Standard Error, and Worst Symmetry. This difference reflects the fact that correlation examines features individually, while the model considers them together when making predictions.

Limitations and Next Steps¶

One limitation of this project is the relatively small dataset of 569 tumor samples, so the model's performance may not fully generalize to other patient populations or datasets, since all samples came from a single institution. In addition, I evaluated the final model using a single train-test split, did not perform extensive hyperparameter tuning, and did not validate the model on an external dataset.

As a next step, I would validate the model on a larger external dataset, test model stability across additional data splits, and explore hyperparameter tuning. I would also examine whether adjusting the classification threshold could further reduce false negatives and improve malignant-class recall. Since lowering the threshold may also increase false positives, I would evaluate this trade-off rather than optimizing recall alone.
